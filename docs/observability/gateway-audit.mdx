The OpenShell gateway emits a structured audit event for every state-changing operation it performs. Creating a workspace, rotating a credential, replacing a policy, opening an exec session, or rejecting a credential each produces one OCSF record. The record names the authenticated principal, the outcome, and a correlation id that ties it back to the request.

Gateway audit events describe changes to the control plane. Per-sandbox events, such as network connections and process lifecycle, are covered in [Sandbox Logging](/observability/logging). Audit events are on by default.

## What Gets Audited

Four OCSF event classes cover the surface.

| Class | Covers | Examples |
|---|---|---|
| Entity Management (3004) | Resource create, update, and delete | Workspaces, workspace members, providers, provider profiles, provider refresh, credentials, sandboxes, sandbox provider attach and detach, ssh sessions, exec and tcp forward sessions, sandbox token issue and refresh |
| Device Config State Change (5019) | Configuration and policy transitions | Settings updates, global and sandbox policy replacement, incremental merges, draft-policy submit, approve, reject, edit, undo and clear, service endpoint expose and delete, interceptor-modified requests |
| Authentication (3002) | Outcomes at the authenticator boundary | Rejected or missing credentials, failed mTLS, anonymous callers, and, behind a toggle, every successful authentication |
| Detection Finding (2004) | Suspicious patterns | A sandbox addressing another sandbox (including a mid-stream `sandbox_id` switch on log push), a sandbox principal calling a user or admin API |

Background work also changes state. Timer-driven credential rotation, reconciliation that removes or fails a sandbox after its backend changes, and creation of the default workspace at startup each emit an Entity Management event attributed to a system actor named `system:<component>`.

Read and list RPCs are not audited. Exec and SSH session input and output never enter a record; session start and the command line do.

## Where Records Appear

Audit events are gateway-origin OCSF events. Every gateway OCSF consumer receives them:

- The gateway console prints each event as a shorthand line. The console follows `RUST_LOG`, so a coarse filter can hide these lines without stopping the other sinks.
- The `[openshell.gateway.ocsf_log]` JSONL file records every audit event, including events without a sandbox. See [OCSF JSON Export](/observability/ocsf-json-export).
- Events about a sandbox also appear in that sandbox's log stream (`openshell logs`, `WatchSandbox`).

Events about a sandbox carry its id in `container.uid`. Gateway-scoped events, such as workspace changes and authentication outcomes, carry no `container` object. Every event names the gateway as the device (`device.type` is `Server`, `device.name` is the gateway name) and `metadata.product.name` is `OpenShell Gateway`. `metadata.uid` is a fresh identifier per event, not a sandbox id.

The shorthand form reads as `CLASS:ACTIVITY [SEVERITY] outcome subject by actor`:

```text
ENTITY:CREATE [INFO] workspace "team-a" by alice(oidc|alice-123)
ENTITY:UPDATE [LOW] FAILED credential "acme/API_KEY" by system:provider-refresh
CONFIG:SETTING_UPDATED [INFO] global setting proposal_approval_mode updated by alice(oidc|alice-123)
AUTHN:LOGON [MED] FAILED openid user:unknown from 10.0.0.9:51044 to openshell-gateway
```

The actor renders as `name(uid)`. A display name can be a self-asserted claim, so the stable identity travels with it.

## Anatomy of an Audit Event

| Field | Meaning |
|---|---|
| `actor.user` | The authenticated principal, taken from the session and never from the request body. An OIDC subject or certificate identity for users, `sandbox:<id>` for sandbox principals, `peer:<replica>` for gateway peers, and `system:<component>` for background work. Authentication events carry it as `user`. |
| `entity` | For Entity Management events, the resource: `type` names it (`workspace`, `provider`, `sandbox`, `ssh_session`, ...), with its `uid` and `name` when known. Workspace members are OCSF `User` entities. |
| `status` | `Success` or `Failure`. A mutation that changed nothing, such as deleting a resource that was already gone, records as `Failure`. |
| `severity_id` | `Informational` for successes, `Low` for failed mutations, `Medium` for authentication failures, and `High` for findings. |
| `unmapped.request_id` | The request's `x-request-id`, so an audit event joins the request trace and the authentication event for the same call. |

Secrets never enter a record. Credential values, refresh material, minted tokens, ssh bearer tokens, and exec environment and stdin are absent by construction. Setting values under keys that look like credentials (`secret`, `token`, `password`, `api_key`, `*_key`, `auth`, ...) are always redacted.

Authorization denials by an authorized caller are not mutation failures. A routine workspace RBAC denial produces no Entity Management event; it remains a plain status and log line.

## Toggles

The `[openshell.gateway.audit]` table, environment variables, and command-line flags control audit events. The gateway resolves them in this order, highest first: flag, environment variable, configuration file, built-in default.

| Setting | Environment variable | Flag | Default | Effect |
|---|---|---|---|---|
| `enabled` | `OPENSHELL_AUDIT_EVENTS` | `--audit-events` | `true` | Master switch for every gateway audit event, including findings and the gateway's policy and service-endpoint config events. |
| `auth_success_events` | `OPENSHELL_AUDIT_AUTH_SUCCESS_EVENTS` | `--audit-auth-success-events` | `false` | Also emit an Authentication event for every authenticated request. Failures are always emitted; successes multiply volume by the request rate. |
| `exec_args` | `OPENSHELL_AUDIT_EXEC_ARGS` | `--audit-exec-args` | `true` | Record the full exec command line. Set `false` to record only the binary name when arguments may carry secrets. |
| `settings_values` | `OPENSHELL_AUDIT_SETTINGS_VALUES` | `--audit-settings-values` | `true` | Record before and after values of changed settings. Set `false` to record key names only. |

```toml
[openshell.gateway.audit]
enabled             = true
auth_success_events = false
exec_args           = true
settings_values     = true
```

On Kubernetes, set the Helm values `server.audit.enabled`, `server.audit.authSuccessEvents`, `server.audit.execArgs`, and `server.audit.settingsValues`.
