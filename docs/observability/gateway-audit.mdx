The OpenShell gateway emits a structured audit event for every state-changing operation it performs. Creating a workspace, rotating a credential, replacing a policy, opening an exec session, or rejecting a credential each produces one [OCSF](https://ocsf.io) record. The record names the authenticated principal, the outcome, and a correlation id that ties it back to the request. Any OCSF-aware collector or SIEM reads the records without a custom parser.

Gateway audit events describe changes to the control plane that governs every sandbox. Per-sandbox events, such as network connections and process lifecycle, are covered in [Sandbox Logging](/observability/logging). Audit events are on by default.

The [Audit Configuration](/observability/audit-configuration) page documents every toggle, and the [Audit Event Reference](/observability/audit-event-reference) catalogs every event with examples.

## What Gets Audited

Four OCSF event classes cover the surface.

| Class | Covers | Examples |
|---|---|---|
| Entity Management (3004) | Resource create, update, and delete | Workspaces, workspace members, providers, provider profiles, provider refresh, credentials, sandboxes, sandbox templates, sandbox provider attach and detach, ssh sessions, exec and tcp forward sessions, sandbox token issue and refresh, provider subject-token exchange |
| Device Config State Change (5019) | Configuration and policy transitions | Settings updates, global and sandbox policy replacement, incremental merges, draft-policy submit, approve, reject, edit, undo and clear, service endpoint expose and delete, interceptor-modified requests |
| Authentication (3002) | Outcomes at the authenticator boundary | Rejected or missing credentials, missing client certificates, anonymous callers, and, behind a toggle, every successful authentication |
| Detection Finding (2004) | Suspicious patterns | A sandbox addressing another sandbox (including a mid-stream `sandbox_id` switch on log push), a sandbox principal calling a user or admin API |

Background work also changes state. Timer-driven credential rotation, reconciliation that removes or fails a sandbox after its backend changes, and creation of the default workspace at startup each emit an Entity Management event attributed to a system actor named `system:<component>`.

Read and list RPCs are not audited. Exec and SSH session input and output never enter a record; session start and the command line do.

Supervisor status reports are not audited either. These RPCs report observed sandbox state rather than change control-plane state: `ReportPolicyStatus`, `ReportProviderReadiness`, `ReportEndpointStatus`, `ReportSandboxConfiguration`, and `FinalizeMainProcessExit`. Their effects surface as sandbox status and platform events in the sandbox log stream. `BeginRootfsTarStaging`, which allocates a short-lived gateway staging slot for a rootfs upload, is also not audited; the sandbox lifecycle event that uses the upload is.

## Where Records Appear

Audit events are gateway-origin OCSF events, so every gateway OCSF consumer receives them. None of these consumers needs audit-specific configuration.

| Destination | Configuration | What it holds |
|---|---|---|
| Gateway console | None | One shorthand line per event. The console follows `RUST_LOG`, so a coarse filter can hide these lines without stopping the other sinks. |
| Sandbox log stream | None | Events about a sandbox, through `openshell logs` and `WatchSandbox`. |
| Gateway OCSF JSONL file | `[openshell.gateway.ocsf_log]` | Every audit event as one OCSF JSON object per line, including events without a sandbox. See [OCSF JSON Export](/observability/ocsf-json-export). |
| OTLP collector | `[openshell.gateway.otlp]` with `export_logs = true` | Every audit event as an OTLP log record, alongside the gateway's other logs and the sandbox logs. |

The JSONL file and OTLP export capture every OCSF event regardless of `RUST_LOG`. Use the `enabled` toggle, not the log filter, to turn audit off.

## Export the Trail Off the Box

The console and the in-memory log stream are enough for local inspection, but they live and die with the process. To retain and analyze the trail, write it to the JSONL file and ship that file, or export it straight to an OpenTelemetry collector. The two sinks are independent and can run together.

To export over OTLP, add `export_logs` to the OTLP table. Log records use the same endpoint and resource attributes as gateway traces:

```toml
[openshell.gateway.otlp]
endpoint    = "http://otel-collector.observability.svc:4317"
export_logs = true
```

Each OCSF record carries the shorthand line as its body and the full OCSF document in the `ocsf.raw` attribute. Set `ocsf_full_payload = false` to export only the shorthand. Authenticate to a hosted collector with the standard OpenTelemetry header variable:

```shell
OTEL_EXPORTER_OTLP_HEADERS="authorization=Bearer <token>"
```

Export is accountable rather than lossless. Records that the gateway cannot deliver are counted and reported downstream as a `telemetry_gap` record, so alert on that record in the collector. For Helm installations, set `server.otlp.endpoint` and `server.otlp.exportLogs: true`. See [OTLP Log Export](/how-it-works/gateways/configuration#otlp-log-export) for record attributes, queue bounds, retries, metrics, and TLS.

## Read a Record

Events about a sandbox carry its id in `container.uid`. Gateway-scoped events, such as workspace changes and authentication outcomes, carry no `container` object. Every event names the gateway as the device (`device.type` is `Server`, `device.name` is the gateway name) and `metadata.product.name` is `OpenShell Gateway`. `metadata.uid` is a fresh identifier per event, not a sandbox id.

The shorthand form reads as `CLASS:ACTIVITY [SEVERITY] outcome subject by actor`:

```text
ENTITY:CREATE [INFO] workspace "team-a" by alice(oidc|alice-123)
ENTITY:UPDATE [LOW] FAILED credential "acme/API_KEY" by system:provider-refresh
CONFIG:SETTING_UPDATED [INFO] global setting proposal_approval_mode updated by alice(oidc|alice-123)
AUTHN:LOGON [MED] FAILED openid user:unknown from 10.0.0.9:51044 to openshell-gateway [reason:token expired]
FINDING:CREATE [HIGH] "Cross-sandbox access attempt" [type:OSGW-CROSS-SANDBOX]
```

The actor renders as `name(uid)`. A display name can be a self-asserted claim, so the stable identity travels with it.

Every audit event carries a common set of fields.

| Field | Meaning |
|---|---|
| `actor.user` | The authenticated principal, taken from the session and never from the request body. An OIDC subject or certificate identity for users, `sandbox:<id>` for sandbox principals, `peer:<replica>` for gateway peers, `anonymous` for unauthenticated callers on a permissive gateway, and `system:<component>` for background work. Authentication events carry it as `user`. |
| `entity` | For Entity Management events, the resource: `type` names it (`workspace`, `provider`, `sandbox`, `ssh_session`, ...), with its `uid` and `name` when known. Workspace members are OCSF `User` entities. |
| `status` | `Success` or `Failure`. A mutation that changed nothing, such as deleting a resource that was already gone, records as `Failure`. |
| `severity_id` | `Informational` for successes, `Low` for failed mutations, `Medium` for authentication failures, and `High` for findings. |
| `unmapped.request_id` | The request's `x-request-id`, so an audit event joins the request trace and the authentication event for the same call. |

Secrets never enter a record. Credential values, refresh material, minted tokens, ssh bearer tokens, and exec environment and stdin are absent by construction. Setting values under keys that look like credentials (`secret`, `token`, `password`, `api_key`, `*_key`, `auth`, ...) are always redacted.

Authorization denials by an authorized caller are not mutation failures. A routine workspace RBAC denial produces no Entity Management event; it remains a plain status and log line.

## Turn It Off

One switch silences every audit emission. The audited operations run unchanged.

```toml
[openshell.gateway.audit]
enabled = false
```

The same switch is available as `OPENSHELL_AUDIT_EVENTS=false`, `--audit-events false`, or the Helm value `server.audit.enabled: false`. See [Audit Configuration](/observability/audit-configuration) for the finer toggles that tune volume and sensitivity without turning the trail off.
