# Policy probes for the on-call triage agent.
# Format: <label>|<allow|deny>|<command>
#
# URLs are written out in full: probe commands run inside the sandbox, where any
# shell variable defined here would be unset.
#
# A command starting with curl is classified by HTTP status; anything else is
# classified by exit status.
#
# Classification, given that every host below resolves:
#   403        -> denied by L7 (host reachable, request refused)
#   000        -> denied by L4 (connection refused before any request)
#   other code -> permitted by policy; the result came from upstream
#
#
# GitHub probes use git rather than curl on purpose. The github-triage profile
# pins its binaries to gh and git, so a curl to api.github.com is denied at L4
# for being the wrong program — which proves binary pinning but says nothing
# about the path rules.
# Grafana is reached by an in-sandbox MCP server over stdio, so what crosses
# the boundary is ordinary HTTPS and the path allowlist is directly probeable.
# curl is an allowed binary for this provider and grants nothing mcp-grafana
# lacks — both are confined to the same paths with the same injected credential.
grafana-read-search|allow|curl -X GET https://grafana.monad.com/api/search
grafana-read-query|allow|curl -X POST https://grafana.monad.com/api/ds/query
grafana-write-dashboard|deny|curl -X POST https://grafana.monad.com/api/dashboards/db
grafana-write-annotation|deny|curl -X POST https://grafana.monad.com/api/annotations
grafana-prom-rules|allow|curl -X GET https://grafana.monad.com/api/prometheus/grafana/api/v1/rules
grafana-irm-read|allow|curl -X POST https://grafana.monad.com/api/plugins/grafana-irm-app/resources/api/v1/IncidentsService.QueryIncidentPreviews
grafana-irm-create|deny|curl -X POST https://grafana.monad.com/api/plugins/grafana-irm-app/resources/api/v1/IncidentsService.CreateIncident
grafana-admin-users|deny|curl -X GET https://grafana.monad.com/api/admin/users
slack-read-history|allow|curl -X GET https://slack.com/api/conversations.history
slack-read-history-post|allow|curl -X POST https://slack.com/api/conversations.history
# Flipped from deny to allow when the agent was asked to report in Slack. The
# permitted write surface is exactly chat.postMessage and chat.delete; the
# probes below assert the rest of Slack is still closed.
slack-write-post|allow|curl -X POST https://slack.com/api/chat.postMessage
slack-write-update|deny|curl -X POST https://slack.com/api/chat.update
slack-file-upload|deny|curl -X POST https://slack.com/api/files.getUploadURLExternal
slack-admin|deny|curl -X GET https://slack.com/api/admin.conversations.search
github-wrong-binary|deny|curl -X GET https://api.github.com/repos/monad-inc/OpenShell
github-org-clone|allow|git ls-remote https://github.com/monad-inc/OpenShell
github-outside-org|deny|git ls-remote https://github.com/torvalds/linux
unrelated-host|deny|curl -X GET https://example.com
